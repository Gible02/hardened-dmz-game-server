## Role

Internet edge. Terminates the ISP handoff, owns **all** NAT for the network, and hands off to
the ASA over a /30 transit link.

## Interfaces

| Interface | Role | Address | NAT role |
|---|---|---|---|
| Gi0/0 | outside — to ONT | 192.168.1.147 | `ip nat outside` |
| Gi0/1 | transit — to ASA Gi0/3 | 192.168.100.1/30 | `ip nat inside` |

## Configuration decisions

| Decision | Choice | Why |
|---|---|---|
| NAT type (outbound) | Overload / PAT | Many internal hosts, one public address |
| NAT type (inbound) | Single-port static DNAT | Exposes one service, not the whole host |
| DNAT target | **192.168.20.10** — the real server | The ASA performs no NAT, so the destination must be the end host |
| Static WAN vs DHCP | Static | ISP offers no DHCP reservation on residential plans |
| Route to DMZ | Static via 192.168.100.2 | The 1921 has no interface in 192.168.20.0/24 |

## Two gotchas worth knowing

**NAT needs both halves.** `ip nat outside` on Gi0/0 **and** the
`ip nat inside source list ... overload` statement. Both were missing initially. The symptom is
identical either way — traffic leaves, nothing returns, and `show ip nat translations` is empty.

**Translation is not reachability.** After the static DNAT was corrected, inbound traffic still
failed because the 1921 had no route to 192.168.20.0/24. NAT rewrote the address, then the
router had nowhere to send it. Both a translation rule and a route are required.
